# Accessibility

Vertex aims to make its documentation, project resources and developer-facing interfaces accessible to as many people as reasonably possible.

## Project Commitments

- Use clear headings and descriptive link text in documentation.
- Prefer semantic HTML and accessible WordPress APIs when framework features generate or interact with user-facing markup.
- Do not rely on colour alone to communicate information.
- Consider keyboard access, screen-reader compatibility and sufficient colour contrast when introducing user-interface features.
- Document known accessibility limitations when they are relevant to a feature.

## Reporting an Accessibility Issue

If you encounter an accessibility barrier in Vertex itself or its project documentation, open an issue using the Feature Request template and select or describe the accessibility concern.

Include, where possible:

- The affected page, component or workflow.
- The assistive technology, browser and operating system involved.
- The steps required to reproduce the issue.
- The expected accessible behaviour and the behaviour observed.

Please do not include personal or sensitive information in a public issue.

Accessibility improvements are considered alongside the project's scope, compatibility requirements and maintenance capacity. This document is an ongoing project commitment, not a claim of formal conformance or certification.
